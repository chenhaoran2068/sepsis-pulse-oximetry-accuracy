# Expected synthetic demonstration outputs

`python demo/run_demo.py` prints `SYNTHETIC_DEMO_PASS <run-id>` after all stages and independent aggregate checks pass. It creates fresh, uniquely named directories immediately below `runs/`. Each stage has a `status.txt`; independent checkers create an `independent_qa_status.txt` where applicable. A zero process exit without the expected QA status is not sufficient.

The standardized-event stage generates 20 invented stays from 19 invented patients. Its deterministic matched-pair totals are 80 for the independently constructed 60-minute analysis and 60 for the independently constructed 5-minute analysis. The downstream clinical and model-input checks must retain those counts. They verify structural Bias arithmetic and pair mean saturation, exact stay/pair linkage, SaO2 time-anchor alignment, unit and state consistency, and rejection of malformed inputs.

The earlier synthetic upstream, imputation-pilot, forest, and four-cohort interface stages have additional `aggregate.tsv` and `checks.tsv` outputs checked by their corresponding `qa/verify_*.py` scripts. Numeric results from the pilot and forest are synthetic test outputs, not reference estimates for the paper.

`python demo/run_models_from_standardized.py --synthetic --mode smoke --run-id NEW_ID` generates a larger heterogeneous invented standardized input and writes distinct `runs/models-NEW_ID-*` stages. It requires a passing input QA, two agreement QAs, two threshold QAs, two 30 × 20 MI/LMM QAs, and a 60-minute RF QA before printing `ANALYSIS_CHAIN_PASS_SYNTHETIC`. The final new-directory MIMIC-shaped **paper-settings** command passed 36 input checks, 16 agreement checks and 19 threshold checks per window, 27 MI/LMM checks per window, and 59 RF checks. The separate five-cohort-shaped synthetic tests passed the same input, descriptive, and formal MI/LMM interfaces; 60-minute RF was checked in smoke mode for each cohort. Each run remains candidate-only. Generated binary files should be judged by schema and logical invariants rather than unstable byte checksums.

After five completed cohort runs, `python demo/render_30_displays.py --run-map PATH --run-id NEW_ID` expects a nine-column five-row run map as defined in the README. It verifies source provenance before creating 30 technical PDFs, receipts, and `display_inventory.tsv`. `tests/verify_30_display_bundle.py` is the independent second-pass command. Its passing marker is `THIRTY_DISPLAY_BUNDLE_INDEPENDENT_QA_PASS displays=30`. The PDFs represent the 30 identities marked in `paper-output-map.md`; they are invented-data technical outputs, not the approved manuscript displays. Supplementary Tables 1-9 and Supplementary Figure 1 are not expected outputs of this contract.
